Challenges
==========
Q.What are your day-to-day DevOps activities?

“In my day-to-day DevOps activities, I work on managing application builds, Docker images, CI/CD pipelines, deployments, and troubleshooting
build-related issues.

One common issue I handle is Docker builds failing because of missing dependencies.

When a developer commits code and triggers the CI/CD pipeline, the Docker image build may fail because some required packages, libraries, or
dependencies are missing.

First, I check the pipeline logs to identify the exact error. Then I review the Dockerfile and verify whether all required dependency files are
copied into the Docker build context.

I also check the dependency installation commands, package versions, and configuration.

After identifying the issue, I update the Dockerfile or dependency configuration, rebuild the Docker image, and verify whether the build is successful.

Once the image is successfully created, the pipeline continues with the next stages, such as pushing the image to the Docker registry and deploying the application.

Finally, I verify that the application is running properly.”


Q. Can you give me an example of a Docker build issue you troubleshoot?

“Yes. For example, suppose a developer commits application code, and the CI/CD pipeline starts automatically.

During the Docker build stage, the pipeline fails with an error indicating that a required dependency or package cannot be found.

I follow these steps:
1. Check pipeline logs: Identify the exact missing dependency or package error.
2. Check Dockerfile: Verify whether the required dependency files are copied into the image.
3. Verify dependencies: Check the dependency configuration file and required package versions.
4. Fix the issue: Update the Dockerfile or dependency configuration.
5. Rebuild the image: Run the Docker build again.
6. Validate: Confirm that the image is built successfully and the application starts correctly.
This helps ensure that the application can be built consistently through the CI/CD pipeline.”

Q. How will you troubleshoot a Maven dependency failure in a Docker build?

“First, I will check the CI/CD pipeline logs to identify the exact Maven dependency error.

Then I will check the pom.xml file to verify whether the required dependencies are declared correctly.

I will check the dependency name, version, repository configuration, and network connectivity.

If any dependency is missing or the version is incorrect, I will update the pom.xml file.

After that, I will rebuild the Docker image and verify whether Maven downloads all required dependencies successfully.

Finally, I will confirm that the Docker build is successful and the CI/CD pipeline proceeds to the next stage.”


Q. Why does a Docker container exit immediately, and how do you troubleshoot it?

“First, I will check the container status using docker ps -a to identify whether the container is running or exited.

Then I will check the container logs using docker logs to identify the application startup errors.

After that, I will use docker inspect to check the container exit code, state, and configuration.

I will also verify the Dockerfile CMD or ENTRYPOINT, environment variables, application configuration, and required ports.

Based on the error, I will fix the issue, restart the container, and verify whether the application is running successfully.”

Q. "Suppose your CI/CD pipeline successfully builds a Docker image, but the image push stage fails with the following error."
denied: requested access to the resource is denied

“My first step is to check the CI/CD pipeline logs to identify the exact error.

If the issue is related to Docker registry authentication, I verify whether the Docker registry credentials are configured correctly in the CI/CD pipeline.

I use a Docker Hub username and a personal access token to authenticate securely.

Then I verify the image name, tag, repository, and push permissions.

After that, I tag the Docker image correctly and push it to Docker Hub.

Finally, I verify whether the image is available in the Docker Hub repository. If the push is successful, the pipeline proceeds to the next stage.”

Q. "Suppose your CI/CD pipeline successfully builds the Docker image and pushes it to Docker Hub. However, during deployment, 
    your application is not accessible in the browser.

    For example, you deployed your Java application, but when you open http://localhost:8080, the application is not responding.

    How will you troubleshoot this issue?"

Q. Your Java application is deployed in Docker, but it is not accessible in the browser. How do you troubleshoot it?

“First, I will check the container status using docker ps -a to verify whether the container is running or stopped.

Then I will check the application logs using docker logs to identify any startup errors.

After that, I will verify the port mapping and check whether the application is listening on the correct port.

I will also check the Dockerfile, application configuration, and environment variables.

Next, I will verify Docker network connectivity and check whether any firewall or security rules are blocking access.

After identifying the root cause, I will fix the issue and test the application again in the browser.”

3. Important commands to remember
Command	Purpose
docker ps -a	Check container status
docker logs <container_id>	Check application logs
docker port <container_id>	Check published ports
docker inspect <container_id>	Check container configuration
docker network ls	List Docker networks
docker exec -it <container_id> sh	Enter a running container
